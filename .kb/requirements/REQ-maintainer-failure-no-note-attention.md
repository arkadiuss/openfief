A maintainer run that is refused or fails must leave no note and no proposal and be audited with its class, and the Inbox must say so only when a scheduled week's run has ended without a note in all of its attempts, retried a quarter of an hour and an hour apart.

## Context

No route, a tier that denies or every model down is a fact for the audit log; a failed first attempt is a bad hour of a provider, and a week whose three attempts all failed is the owner's to look at. The author answered on 2026-11-13 that the weekly run retries within its window like D-198: three attempts, a quarter of an hour and then an hour apart; every attempt is kept with its error class and never its text (GR-12); an owner-asked run's failure doesn't count; the Monday 06:30 slot is fixed. This replaces the earlier rule of two weekly failures in a row.

## Source

> Weekly run retries within its window like D-198: River MaxAttempts 3 with backoff about 15 min then 1 h. Raise maintainer-failing when a scheduled week's run fails ALL its attempts (not after N weeks); clear it on the next success. Keep every attempt with its error class (never text, GR-12). Owner-asked failures don't count.
