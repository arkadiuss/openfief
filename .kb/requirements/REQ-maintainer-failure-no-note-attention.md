A maintainer run that is refused or fails must leave no note and no proposal and be audited with its class, and the Inbox must say so only when the weekly run has ended without a note twice in a row.

## Context

No route, a tier that denies or every model down is a fact for the audit log; one failed week is a bad hour of a provider, two is the owner's to look at (the count is the author's to change).

## Source

> Failure: no route / tier denies / all models down -> no note, an attention item only if the weekly run failed N times in a row; audit outcome failed/refused with class; never partial proposals.
