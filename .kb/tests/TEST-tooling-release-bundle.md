Runs scripts/release-bundle.sh against the real deploy/ and a throwaway one, with synthetic digests. The install file pins exactly the operator, egress proxy and core images to the given repository and digest, from arguments matched by name or from images.yml's digest files under a lower-cased prefix (ignoring plugin and demo-seed files), or to all-zeros placeholders for a dry run, and keeps SpiceDB's third-party image, by tag and digest, as deploy/spicedb pins it, with SpiceDB's tag the Taskfile's SPICEDB_VERSION; the credentials Job runs the core's image at the digest the core runs, with init-credentials (D-216), is the install's only Job and carries the label app.kubernetes.io/name=openfief-init-credentials on itself and its pod, and is named openfief-init-credentials-<version> with the version lowercased and its dots as dashes (2026.11.0-alpha.1 and 2026.11.0-RC.2 checked), so each release has a Job of its own; the Role of that Job is the only Role or ClusterRole in the install that grants create on secrets, wildcards included, grants that and nothing else, and is bound to the Job's ServiceAccount alone; the CRDs file holds only the namespace and the CRDs; the database file holds the Cluster openfief-db with the managed role spicedb and the Database spicedb; the same images in another order give byte-identical files. It refuses a missing image or digest file, a digest that is not sha256, an image by tag, a third party's image by tag alone, two images for one name, an image the install doesn't name, digest files without a prefix or together with arguments, placeholders with images or with VERIFY, VERIFY without REPO, a version that can't name a file, one that makes the Job's name longer than 63 characters, a base without the credentials Job and a base that names its image by tag, and a failed run writes nothing. Signature verification (VERIFY=1) needs cosign and keyless signatures, so it runs only in the release workflow.
