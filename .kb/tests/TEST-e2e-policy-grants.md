Runs against the real stack, restarting the core with --authz=policy in place of its --authz, as an owner who opts out of SpiceDB, the default the install and the demo run, does, and restoring its args after: the suite's pass of the policy. A token granted one account lists that account alone over /v1 and its MCP tool value differs from the household token's, with the switch and the MCP toggle on; the household token lists every demo account; no token is listed an item of an unmapped broker account, which is tied to no account; and the owner's session and a demo session list every account and the built-in UI's accounts page shows each. A false pass would be a core that never left SpiceDB, which the one-account token listing the one account under the policy would not rule out; the restart is the Deployment's own rollout, waited for.
